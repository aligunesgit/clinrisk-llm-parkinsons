# ClinRisk-LLM for Parkinson's Disease Biosignals

Analysis code, frozen policy, LLM prompts, regenerated policies and aggregate results for the study
**"LLM-Guided Adaptive Cost Calibration in Active Learning for Parkinson's Disease Biosignals"**
(Gülez, Güneş, Kocabıçak; submitted to *International Journal of Molecular Sciences*).

The study asks whether cost-sensitive active learning (AL) lowers a prespecified asymmetric loss
(false negative : false positive = 4 : 1) on participant-level gait and speech data. It separates
the contributions of class-weighted training, risk-aware querying and an LLM-derived calibration
policy (ClinRisk-LLM). The LLM is called **once, before evaluation**, to translate a safety
specification into a deterministic policy. That policy is frozen and replayed with no further LLM
calls. It never labels data and never predicts any participant's diagnosis.

> **Key findings of the revised analysis.** The cost reductions come from cost-sensitive learning.
> A symmetric model with a post-hoc threshold matches them for gait, and risk-aware querying adds no
> consistent benefit across paired splits. Gait remains roughly level with a trivial refer-all policy.
> ClinRisk-LLM adapts to each modality but does not consistently outperform simpler policies. Its gait result was
> not reproduced by 40 regenerations across three LLMs (gait $C_4$ 52.1–75.8 vs. the original 47.6).

## 2. The LLM component

### 2.1 Provenance of the original policy (please read)
The frozen policy was generated on **23 August 2026** with **Claude Sonnet 5** through the
**Claude Code CLI**. The authors checked the returned rules against the specification and transcribed
them into `llm_policy()` in `experiments/clinrisk_agent_analysis.py`. That function is the policy
used in every result. **The verbatim prompt of this original generation was not archived and
cannot be provided.** During peer review, the specification was written out in full from the
documented design (inputs, action space and four safety clauses) as `experiments/revision/policy_prompt.md`.
It is the exact prompt used for all regenerations, so those results are fully reproducible.

### 2.2 Safety specification (summary; full text in `policy_prompt.md`)
1. Missed PD cases cost more than false alarms, but specificity is protected before sensitivity pressure is increased.
2. Sensitivity pressure is escalated only when specificity has headroom and sensitivity is poor or declining.
3. If specificity collapses, the risk weight is reduced at once and targeted querying is used instead.
4. Actions change gradually, and the risk weight is frozen late in the labelling budget.

### 2.3 Context variables (computed from the labelled development pool only)
| Key | Definition |
|---|---|
| `budget` | fraction of the development pool already labelled |
| `sens`, `spec` | three-fold out-of-fold sensitivity / specificity of a symmetric RBF-SVM fitted on the labelled set; `None` if either class has fewer than 3 labels (cold start) |
| `prevalence` | fraction of PD among labelled observations |
| `margin` | median absolute SVM decision value on the unlabelled pool under the previous risk weight |
| `neg_frac` | fraction of unlabelled observations predicted negative |
| `trend` | `declining` / `flat` / `improving`: OOF sensitivity versus the previous step (±0.02) |

**Actions:** risk weight `r` ∈ {1,2,3,4} (positive-class SVM weight) and negative-side query priority
`a` ∈ {1,2,3,4} (uncertainty scores of predicted negatives are divided by `a`).

### 2.4 Regenerated policies
`experiments/revision/policy_regeneration.py` sends `policy_prompt.md` to the model in independent
`claude -p` sessions. It archives each response verbatim, statically checks the returned Python
(no imports, I/O or attribute access other than `ctx.get`; only `min/max/abs/int/round` and locally
defined helpers may be called), and replays every valid policy unchanged on all 60 splits.

| Model (Claude Code CLI) | n | Gait $C_4$ mean (range) | Speech $C_4$ mean (range) |
|---|---|---|---|
| original frozen policy (`claude-sonnet-5`, Aug 2026) | 1 | 47.60 | 24.69 |
| `claude-sonnet-5` | 20 | 67.27 (55.90–75.83) | 24.78 (24.51–24.93) |
| `claude-opus-5-5` | 10 | 55.33 (52.10–57.00) | 24.78 (24.49–25.04) |
| `claude-haiku-5-5` | 10 | 65.99 (63.07–70.00) | 24.77 (24.49–24.84) |

## 3. Data

The datasets are not redistributed. Place them as follows:

| Dataset | Source | Local path |
|---|---|---|
| Gait in Parkinson's Disease v1.0.0 | https://physionet.org/content/gaitpdb/1.0.0/ (doi:10.13026/C24H3N) | `datasets/gait/physionet-vgrf/` (all `*.txt` incl. `demographics.txt`) |
| Parkinson's Disease Classification | https://doi.org/10.24432/C5MS4X | `datasets/pd_speech_features.csv` |
| Parkinsons (Little et al.), replication only | https://doi.org/10.24432/C59C74 | `datasets/voice/uci-parkinson-voice/parkinsons.data` |

**Gait cohort note.** The loader uses the first walk (`*_01.txt`) of each participant. No recording
fails the quality rules (20 N contact threshold, plausibility bounds on stride/swing/stance, ≥5 valid
strides per foot). One control in `demographics.txt` has no recording, so a complete download yields
**165 participants (93 PD, 72 controls)**, as used in the revised manuscript. Verify your download with
`shasum -a 256 -c SHA256SUMS.txt` inside the data folder. An earlier version of the analysis
silently lost five Ga PD participants (GaPt12–GaPt16) to an incomplete download (empty files). The
loader treats an empty file as unreadable, so a truncated download changes the results without an error.

## 5. Step-by-step reproduction

All steps are deterministic (fixed seeds). `bash experiments/revision/rerun_all.sh` runs steps 1–9 in order. Steps 1–2 reproduce the original tables. Steps 3–9 reproduce the
revision analyses. Run from the repository root. Approximate run times for the revision steps are for a 10-core laptop.

| Step | Command | Produces (manuscript item) | Time |
|---|---|---|---|
| 1 | `python experiments/revised_cal_analysis.py` | component ablation, full-pool references (Tables 3, 5; Figs 2–5) | longest step |
| 2 | `python experiments/clinrisk_agent_analysis.py` | adaptive policies incl. frozen ClinRisk-LLM (Table 6; Figs 6–7) | long |
| 3 | `cd experiments/revision && python burden_dca.py` | refer-all floor, burden per 1000, decision curves (Table 7; Fig 8) | <1 min |
| 4 | `python prevalence_matched.py` | prevalence swap (Fig 9) | <1 min |
| 5 | `python external_validation.py` | leave-one-study-out gait, UCI speech replication (Table 8) | <1 min |
| 6 | `python reviewer2_analyses.py all` | threshold-tuned AL (Table 3), k-means policies (Table 9), OOF stability (Fig 10), speech PCA | ~7 min |
| 7 | `python paired_differences.py` | paired split-level differences (Table 4) | <1 min |
| 8 | `python policy_regeneration.py evaluate` (and with `POLICY_MODEL=claude-opus-5-5` / `claude-haiku-5-5`) | replays the archived regenerated policies (Table 10) | ~3 min each |
| 9 | `python make_revision_figures.py && python make_supplements.py` | revision figures and Supplementary Files S1–S2 | <1 min |

Steps 3, 6 and 7 read the record files written by steps 1–2. Regenerating the policies themselves
(`python policy_regeneration.py generate N`) calls the LLM and requires an authenticated Claude Code
CLI. The archived responses in `results/revision/regenerated_policies*/` make this step optional.

## 6. Evaluation protocol (summary)

- 60 class-stratified 70/30 pool/test splits, participant-level. The splits overlap, so intervals are descriptive bootstrap intervals and paired split-level differences are reported instead of p-values.
- Standardization and the RBF bandwidth are fitted on the development pool only. The test data never influence acquisition, thresholds or policy decisions.
- RBF-SVM, C = 1. Label-blind initial sample of 10. Batches of 5 chosen from 25 candidates.
- Common loss $C_4 = 100\,(4\,\mathrm{FN} + \mathrm{FP})/N$, equivalent to net benefit at threshold probability 0.2.
